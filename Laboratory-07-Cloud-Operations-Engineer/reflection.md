# Mission Reflection

Checking the host server's resources matters even when containers are running perfectly because containers share the underlying host's CPU, memory, and disk. A container can be functioning correctly from the application's perspective while the host itself is running low on memory or disk space, which can cause the kernel to kill processes, throttle performance, or crash the entire server regardless of how healthy any individual container looks. Host-level monitoring catches problems that container-level health checks alone would miss.

If a user complains they cannot log into a web application, the docker logs command would let me pull the exact HTTP requests the application received around the time of the failure. I could look for failed authentication attempts, error status codes, or stack traces tied to the login request, which narrows the problem down to a specific cause instead of guessing whether it's the application, the database, or the network.

Monitoring logs and monitoring metrics serve different purposes. Logs are a historical, detailed record of discrete events, such as individual HTTP requests and their outcomes, useful for investigating a specific incident after it happens. Metrics are continuous, aggregated numerical data, like CPU percentage or memory usage, useful for spotting trends and overall health in real time. Logs tell you what happened; metrics tell you how the system is performing right now.

Large enterprise companies monitoring thousands of containers rely on centralized observability platforms rather than checking each container by hand. Tools like Prometheus continuously scrape and store metrics from every container and host, while Grafana turns that data into dashboards and alerts engineers automatically when thresholds are crossed. Centralized log aggregation tools collect logs from all containers into one searchable system as well, so engineers don't have to run docker logs on each container individually.

My ability to troubleshoot Linux environments has improved noticeably across these labs. I've gone from running single commands and hoping they worked to systematically checking host resources, container state, logs, and live metrics as part of one coherent diagnostic process. Reading command output critically, rather than just executing commands, now feels like a normal part of my workflow.
